First release of Gailan, a fork of [Übersicht](https://github.com/felixhageloh/uebersicht)
by Felix Hageloh. Widgets work the same way they always have; the app around them has been
brought up to date.

Gailan is not backwards compatible with Übersicht and does not upgrade it. The app name,
bundle id and support directory are different, so the two install side by side. Widget code
carries over; settings and the widgets folder have to be moved by hand. Node went from 16 to
26, so a widget relying on old Node behaviour or a native module built for Node 16 needs
rebuilding.

## What changed since Übersicht 1.6.82

**Runtime and build**

- Bundles Node 26 instead of Node 16. The binaries are fetched and checksummed at build
  time rather than committed, since a darwin `node` is now larger than GitHub allows in a
  repository.
- Requires macOS 13.5, which Node 26 and the current system APIs need. The app will not
  launch on older versions.
- CoffeeScript 2, React 19, Emotion 11, browserify 17, ws 8, and current Babel. The
  deprecated `coffee-script` package is gone.
- Every deprecated macOS API is replaced: login items use `SMAppService`, notifications use
  the UserNotifications framework, Sparkle uses `SPUStandardUpdaterController`, and the
  archiving, FSEvents and window-mask calls are the supported ones. The app compiles with
  no deprecation warnings.

**Widgets**

- `.tsx` widgets are supported and are what the sample widget is written in. Types are
  stripped when the widget is bundled, not checked.
- Widget commands run through zsh, with fish available in Preferences. Übersicht used bash.
- Widgets can read the app's light/dark setting from a `data-appearance` attribute as well
  as `prefers-color-scheme`.
- [Liquid Glass](https://github.com/samasante/liquid-glass) by Sam Asante is bundled, so a
  widget can import `Glass` and refract whatever is behind it.

**Security**

- Every request between the app, the server and the widgets carries a token generated per
  launch and handed over on stdin. Anything running on the machine could previously post to
  the command endpoint and run shell commands as the user. This is a reworked version of
  [uebersicht#486](https://github.com/felixhageloh/uebersicht/pull/486) by execjosh, with a
  constant-time comparison and a cookie parser that cannot throw.

**Preferences**

- Grouped into sections, with new settings for the shell, the appearance, and whether
  widgets float above other windows. The floating option is a reworked version of
  [uebersicht#548](https://github.com/felixhageloh/uebersicht/pull/548) by clubanderson
  that changes window levels in place instead of rebuilding every window.

**Fixes**

- Deleting a folder no longer removes widgets from unrelated folders whose names start with
  the same characters.
- Widget settings could be written as invalid JSON when several changes landed at once,
  which lost every widget's settings silently.
- An unreadable `main.css` in the widgets folder crashed the server on every page load.
- The prefs window logo was never copied into the widgets folder, because the app asked for
  a file name that did not exist.
- The status menu rebuild and the widget tree walk no longer do work proportional to the
  square of the widget count.
